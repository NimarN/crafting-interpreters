The Lox Language

Dynamic Typing 
    - Lox is dynamically types, meaning variables can store values of any type , and a single 
        variable can store values of different types at different times. 
    - Performing an operation on valus of the wrong type will be detected as an error at runtime and reported
    - Static Type System is more work to learn and implement. 


Automatic Memory Management
    - Two main techniques for managing memory 
        - reference counting 
        - tracing garbage collection (garbage collection or GC)
    - Ref counters are much simpler to implement however has their limitations, eventually languages that started with reference counting 
        ended with tracing GC
    - In the book we will be writing our own garbage collector

Data types
In Lox there are the following data types: 
    - Booleans: 
        - Lox has a dedicated Boolean type 
            true;
            false;
    - Numbers: 
        - Lox has only one kind of number: doble-precision floating point
            1234; // An Integer
            12.34; // A decimal number 
    - Strings 
        - Enclosed in double quotes
            "I am a string"
    - Nil 
        - In lox: nil
        - There are good arguments for not having a null value in a language since null pointers can cause issues.
            If we were developing a statically typed language it would be worth to leave it out. But in a dynamically typed language , 
            eliminating it is harder than having it.

Statements 
    - Expressions main job is to produce a value, a statement's job is to produce an effect. 
    - ex: 
        print "Hello, world";
        "some expression";

        If you want to pack a series of statements where a single one is expected you can wrap them in 
        a block : 

        {
            print "One statement";
            print "Two statements";
        }
Variables
    - You declare variables using var statements. If you omit the initializer, the value defaults to nil
    - ex: 
        var imAVariable = "here is my value";
        var iAmNil;
    - Once delcared you you can naturally access and assign a variable using its name 
    - ex: 
        var breakfast = "bagels";
        print breakfast; // "bagels"
        var breakfast = "eggs"; 
        print breakfast // "eggs"

Functions
    - function call expression looks the same as it does in c 
    makeBreakfast(bacon, eggs, toast);
    makeBreakfast()
    - paranthesis are mandatory to execute the function
    - defining a function is done with fun 
        fun printSum(a, b) {
            print a + b;
        }
    - arguments vs parameters
        - argument is an actual value you pass to a function when you call it 
        - parameter is a variable that holds the value of the argument inside the body of the function

    - body of a function is always a block. Inside you can return a value using the return statement . If execution hits the 
        end of the block without return , nil is returned implicitly

Closures
    - Functions are first class in Lox, meaning they are real values that you can get a reference to, store in variables, pass around , etc
        fun addPair(a, b) {
            returns a + b
        }

        fun identity(a) {
            return a
        }

        print identity(addPair)(1, 2) // prints 3

    - Since function declerations are statements you can declare local functions inside another function

        fun outerFunction() {
            fun innerFunction() {
                print "I'm Local!"
            }
            
            localFunction();
        }

    - Combining local functions, first class functions and block scope you get the following: 
        fun returnFunction() {
            fun inner() {
                print outside;
            }

            return inner;
        }

        var fn = returnFunction();
        fn()

        - Here inner() access a local variable declare outsid of its body in the surrounding function 
        - FOr this to work, inner() has to "hold on" to references to any surrounding variables so that it stays around even after the outer function has returned.
        - We call functions that do this closures. 

Classes 
    - Two approaches to objects 
        Classes 
        Prototypes
    - In class based languages there are two core concepts: instances and Classes 
        Instances store the state for each object and have a regerence to the instance's class
        Classes contain the methods and inheritance chain

    - Prototype based languages only have objects and each individual object may contain stte and methods
        Objects can directly inherit from eachother ( also known as delegate )
    
    - Lox will be a class based language 


Classes in Lox 
    - In Lox you declare a class and its methods

    class Breakfast {
        cook() {
            print "Eggs are frying";
        }

        serve(who) {
            print "Enjoy your breakfast, " +  who + ".";
        }
    }

    - The body of a class contains its methods. They look like function declarations but without the fun keyword
    When the class declaration is executed, Lox crats a class object and stores that in a variable named after the class. 
    Just like functions, classes are first class in Lox

    vat someVariable = Breakfast;

    someFunction(Breakfast);

    - In lox, calling a class like a function will produce a new instance of itself
    
    var breakfast = Breakfast();
    print breakfast; // "Breakfast instance"

Instantiation and initialization 
    - Lox allows you to freely add properties onto objects
        breakfast.meat = "sausage";
        breakfast.bread = "sourdough";
    
    - Assigning to a field creates it if it doesn't already existing

    - If you want to access a field or method on the current object from withn a method you use this 

        class Breakfast {
            serve (who) {
                print "Enjoy your " + this.meat + " and " + this.bread + ", " + who + ".";
            }
        }
    
    - To ensure an object is in a valid state when it is created you can define an initializer. 
        If your class has a method named init() it is automatically called when the object is constructed. 
    
    class Breakfast {
        init(meat, bread) {
            this.meat = meat; 
            this.bread = bread;
        }
        // ...
    }
    var baconAndToast =  Breakfast("bacon", "toast");
    baconAndToast.serve("Dear Reader")

Inheritance  
    - Lox supports single Inheritance. When you declare a class, you can specify that it inherits from using a less-than < operator

    class Brunch < Breakfast {
        drink() {
            print "How about a Bloody Mary?";
        }
    }

    - every method defined in the superclass is also available to its subclasses. 

        var benedict = Brunch("ham", "English muffin");
        benedict.serve("Noble Reader");
    
    - Event the init() method gets inherited but in practice the subclass can define its own init by using super

        class Brunch < Breakfast {
            init(meat, break, drink) {
                super.init(meat, bread);
                this.drink = drink
            }
        }
